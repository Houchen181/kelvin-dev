            Instruments

            For everyone on this computer.

            Connected instruments
            When Kelvin starts without a lab of your own, it asks each connected instrument who it is (nothing is set) and connects the ones it knows; until you review their limits, Kelvin asks you before each output change on them. When you name an instrument in a chat, Kelvin sets it up the same way. Each instrument gets a folder in ~/Kelvin/instruments with its identity, settings and manual, refreshed on every start. Fetching a manual sends only its address to the maker's website. Looking on the local network finds instruments that announce themselves (LXI); the first time, Windows may ask whether Kelvin may use the network: allow private networks. For an instrument it doesn't know, Kelvin finds the maker's manual and writes a draft card with your default model (it sends the maker, the model and the manual's command pages, never the serial number). Every setting and output change on a draft asks you until you review it.

            Data & reports

            Data folder
            Where Kelvin saves runs (each in its own dated folder with its data, the instrument settings and the analysis), the lab record of every command and approval, and reports. A lab server or a synced drive works. Chats, settings and API keys stay in ~/Kelvin.
            Every run's folder gets its data as data.csv (always). The reports folder holds a folder per project, with its master report, a report per device, an index of every scan (index.csv) and a dated copy each day; queues and reports you ask for have their own folders.

                Literature

                Literature and web search
                Kelvin searches arXiv and journals (through OpenAlex) and reads papers to plan experiments and check results. It also searches the web, through your model service's own web search, and reads web pages and manuals: instruments' manuals, makers' pages, documentation. Only the search words and the pages it opens leave this computer, never your data or chats. Switch it off for confidential work.

                Notifications

                Notifications
                Alarms, approvals that wait for you, and finished runs show here; allow system notifications to see them when Kelvin is in the background.
                Only what you tick goes to that address, which then holds lab details; use a private topic or channel.

                Phone

                Phone access
                Paired phones can see the lab, runs and alarms, stop a run and decline requests; phones you allow to control can also chat and approve. Settings, instruments and the lab config stay on this computer.
                  Away from the lab, install Tailscale on this computer and the phone; Kelvin then shows its Tailscale address too, and the connection is encrypted. Plain Wi-Fi traffic is not, so on a shared network prefer Tailscale. Phone can't connect? It must be on the same Wi-Fi as this computer, and the computer's firewall must let it in. Many university, housing and hotel Wi-Fi networks keep devices apart; on those, use Tailscale on both.

                        Manage usage

                        Your instrument cards

                        A card tells Kelvin how to talk to an instrument model. For one Kelvin doesn't know, give the command reference from its manual, or the maker's example scripts, and a model drafts the card. Try it on the instrument, compare its readings with the front panel, and fix it until they agree. New cards are drafts: on real hardware their readings work, so you can try them, but Kelvin asks you before each setting or output change until you mark the card reviewed.

                          New card from a manual or example scripts
                          A PDF manual? Copy the command pages from your PDF viewer and paste them here. Example scripts? , several at once: the scripts, a DLL's header file, the README. What you give goes to the model you pick.

                            Trying only asks who the instrument is and reads every reading; it sets nothing.
